# React Native CLI — Platform-Specific Quirks — Platform.OS and file-suffix conventions

_Last updated: 2026-08-24_

## Overview

React Native gives you two distinct mechanisms for forking behavior per platform: a runtime check (`Platform.OS`/`Platform.select`) and a build-time file-resolution convention (`.ios.js`/`.android.js`/`.native.js`). They look interchangeable at a glance but differ in what actually ships in each platform's bundle, which is what should decide which one to reach for.

## `Platform.OS` — a runtime check

```js
import { Platform } from 'react-native';

if (Platform.OS === 'ios') {
  // iOS-specific logic
} else {
  // Android
}
```

`Platform.OS` is a string (`'ios'`, `'android'`, also `'windows'`/`'macos'` where those platforms apply) evaluated at runtime inside a single JS bundle containing both branches. Nothing is stripped at build time — both code paths ship to both platforms; the `if` just decides which one executes.

`Platform.select()` is a shorthand for picking a value by platform inline, common in styling:

```js
const styles = StyleSheet.create({
  container: {
    ...Platform.select({
      ios: { shadowColor: '#000', shadowOpacity: 0.2 },
      android: { elevation: 4 },
    }),
  },
});
```

## File-suffix conventions — a build-time / bundler-level split

```
Button.ios.js
Button.android.js
```

```js
// elsewhere in the app
import Button from './Button';
```

Metro's module resolver picks the suffixed file matching the platform it's currently bundling for — `import './Button'` resolves to `Button.ios.js` when bundling for iOS, `Button.android.js` for Android. A `.native.js` suffix also exists, matching both iOS and Android while specifically excluding web (relevant when `react-native-web` is in the mix).

## Why the distinction matters: runtime vs. bundle-time

- `Platform.OS` → **one file, two branches, both shipped**. Fine for a small conditional (a style tweak, a single prop difference).
- `.ios.js`/`.android.js` → **two separate files; each platform only ever bundles and ships its own**. The other platform's file doesn't exist in that bundle at all — no dead code, no unused imports pulled in from a native dependency the other platform doesn't need.

The deciding factor is how much code diverges. A one-line difference → `Platform.OS`/`Platform.select`. A component whose entire implementation differs (e.g. one wraps a native iOS date picker, the other wraps a Material date picker with a completely different API surface) → separate `.ios.js`/`.android.js` files, since cramming that into `if` branches in one file gets unreadable and drags in both native dependencies' imports regardless of platform.

## Gotcha: forgetting the base file

If `Button.ios.js` exists but `Button.android.js` doesn't, `import './Button'` simply fails to resolve on Android — Metro doesn't fall back to a non-suffixed file unless one also exists. A base `Button.js` plus a `Button.ios.js` override **does** work, with the suffixed file taking priority on its platform. This is a common trip-up when a component starts platform-agnostic and later needs a one-platform override: the base file still needs to exist for whichever platform doesn't get its own suffixed version.

## TypeScript note

Both mechanisms work fine with `.tsx`/`.ts` — the suffix goes before the extension (`Button.ios.tsx`), and `@types/react-native`/the RN TS config understands the suffix convention, type-checking each platform variant independently.

## Key Takeaways

- `Platform.OS`/`Platform.select` is a runtime branch inside one shared bundle; file suffixes are a build-time resolution that excludes the other platform's file entirely.
- Choose based on how much the implementation diverges, not just how many platforms are involved — small conditionals stay in one file, structurally different implementations become separate files.
- A suffixed override (`Button.ios.js`) still needs a base file (`Button.js`) or a matching suffix for every other platform, or resolution fails on the platform with no matching file.
- `.native.js` targets iOS + Android together while excluding web, for repos using `react-native-web`.
